# AISA Tracker

เว็บแอปติดตามความพร้อมสอบ **AISA** (CISA ระดับ Foundation ของตลาดหลักทรัพย์ฯ)
วัดผลระดับ **วัตถุประสงค์การเรียนรู้ (LOS)** และ **เวลาต่อข้อ** ไม่ใช่แค่ชั่วโมงที่นั่งอ่าน

ใช้กันในวงปิด — ล็อกอินได้เฉพาะอีเมลที่อยู่ในรายชื่อที่อนุญาต ไม่มี leaderboard
แต่ละคนเห็นเฉพาะข้อมูลของตัวเอง

## ทำไมออกแบบแบบนี้

| สิ่งที่ทำ | เหตุผล |
|---|---|
| วัดที่ LOS ไม่ใช่ชั่วโมง | เกณฑ์ผ่านคือคะแนน "อ่อนวิชาตราสารหนี้" บอกแล้วทำอะไรไม่ถูก แต่ "พลาด LOS 5.2 เรื่อง duration" เปิดอ่าน 3 หน้าจบ |
| งบเวลาต่อข้อ **แยกตามวิชา** | ข้อจรรยาบรรณอ่าน 40 วิจบ ข้อคำนวณ 3 นาทียังไม่พอ ถ้าใช้ 90 วิเท่ากันหมด ธง "ช้า" จะขึ้นตลอดจนหมดความหมาย |
| จรรยาบรรณตก = แดงทั้งหน้าจอ | เกณฑ์ผ่านมี 2 ชั้น (รวม 70% **และ** กลุ่มวิชาที่ 1 ≥ 70%) กับดักที่ใหญ่ที่สุดคือคะแนนรวมสวยแต่ตกเพราะวิชาที่มองข้าม |
| ไม่มีปุ่มหยุดเวลา | มีเมื่อไหร่ สถิติเวลาทั้งระบบเชื่อไม่ได้ทันที ซึ่งเป็นหัวใจของแอปนี้ |
| กันโจทย์ 20% เป็นชุดสำรอง | ทำโจทย์ชุดเดิมซ้ำแล้วคะแนนขึ้นเพราะจำเฉลยได้ ไม่ใช่เพราะเก่งขึ้น ต้องมีการวัดที่สะอาดอย่างน้อยหนึ่งครั้ง |
| ไม่มี LLM ใน runtime | เนื้อหาตัวจริงอยู่ในมือแล้ว การให้ AI สรุปทับคือจ่ายเงินเพื่อได้ข้อมูลที่แม่นน้อยลง การสกัด PDF ทำตอน dev ครั้งเดียว |
| วันสอบเป็น config ไม่ดึงเว็บ | ตลท. ประกาศรอบสอบปีละ 4 ครั้ง การดูแล scraper แพงกว่าการแก้ไฟล์ 4 บรรทัด |

## ติดตั้ง

### 1. สร้างโปรเจกต์ Supabase

รัน `supabase/schema.sql` ใน SQL Editor ครั้งเดียว

### 2. เปิด Magic Link

**Authentication → Providers → Email** เปิดไว้ (ค่าเริ่มต้นเปิดอยู่แล้ว)
ไม่ต้องตั้ง Google Cloud ไม่ต้องมีรหัสผ่าน

**Authentication → URL Configuration**

| ช่อง | ค่า |
|---|---|
| Site URL | `http://localhost:3210` |
| Redirect URLs | `http://localhost:3210/**` |

> **ข้อจำกัดของแพลนฟรี:** แก้ email template ไม่ได้จนกว่าจะต่อ custom SMTP
> (หน้า Authentication → Emails จะขึ้นแถบ "Set up custom SMTP to edit templates")
> เทมเพลตเริ่มต้นใช้ `{{ .ConfirmationURL }}` ซึ่งเป็น PKCE ผูกกับเบราว์เซอร์ที่ขอลิงก์
>
> **กติกาที่ต้องรู้: ขอลิงก์บนเครื่องไหน ต้องเปิดเมลบนเครื่องนั้น**
> ขอจากคอมแล้วไปกดในเมลบน iPad จะไม่ผ่าน และถ้ากดลิงก์จากในแอป Gmail
> ให้เปิดใน Safari แทน in-app browser
>
> ถ้าอยากให้ข้ามเครื่องได้: ต่อ SMTP ฟรี (Resend/Brevo) ที่ Authentication → Emails → SMTP Settings
> แล้วแก้ลิงก์ในเทมเพลตเป็น
> `{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&type=magiclink`
> — `/auth/callback` รองรับรูปแบบนี้อยู่แล้ว ไม่ต้องแก้โค้ด

> **โควตาอีเมล:** SMTP ในตัวของ Supabase จำกัดราว **2-4 ฉบับ/ชั่วโมงทั้งโปรเจกต์**
> สำหรับ 3-5 คนที่ล็อกอินทิ้งไว้ยาว ๆ พอ

### 3. ใส่ตัวเองและเพื่อนใน allowlist

ไม่มีใครสมัครเองได้ ต้องมีชื่ออยู่ก่อน — คนที่ไม่อยู่ในรายชื่อจะถูกปฏิเสธตั้งแต่ตอนกดขอลิงก์
(trigger ทำงานที่ระดับฐานข้อมูล ไม่ขึ้นกับว่าล็อกอินด้วยวิธีไหน)

```sql
insert into allowlist (email, is_admin, note) values
  ('you@example.com',    true,  'เจ้าของระบบ'),
  ('friend@example.com', false, 'New Breed 2026');
```

### 4. ตั้งค่า env

```bash
cp .env.example .env.local
```

ใส่ `NEXT_PUBLIC_SUPABASE_URL` และ `NEXT_PUBLIC_SUPABASE_ANON_KEY` จาก Settings → API

จากนั้นเพิ่มอีกบรรทัดใน `.env.local` **เฉพาะบนเครื่องคุณ** สำหรับสคริปต์ seed:

```
SUPABASE_SERVICE_ROLE_KEY=<service_role จาก Settings → API>
```

> `service_role` **ข้าม RLS ทั้งหมด** — อ่านและแก้ข้อมูลของทุกคนได้โดยไม่สนใจ policy
> ไม่มีโค้ดในแอปที่อ่านค่านี้ มีแค่ `tools/seed.mjs` ที่รันบนเครื่อง
> จึงไม่ได้ใส่ไว้ใน `.env.example` เพื่อไม่ให้ Vercel เสนอเป็นตัวแปร production
> **ห้ามใส่บน Vercel** ถ้าเห็นมันในรายการให้กดลบแถวนั้นทิ้ง

### 5. สร้างและนำเข้าหลักสูตร

`data/curriculum.json` **ไม่ได้อยู่ใน repo** (เป็นข้อความจากคู่มือของ ตลท.) ต้องสร้างเองจากไฟล์
`LOS_CISA-Foundation.pdf` ที่โหลดได้จาก
[หน้าหลักสูตร CISA Foundation ของ ตลท.](https://www.set.or.th/th/education-research/education/professional/new-cisa/foundation)

```bash
pip install pymupdf
python tools/curriculum.py /path/to/LOS_CISA-Foundation.pdf data/curriculum.json
node tools/seed.mjs
```

จะได้ 11 วิชา · 69 บท · 515 LOS พร้อมสัดส่วน % ข้อสอบทางการ

### 6. รัน

```bash
npm run dev
```

เปิด http://localhost:3210

## ขอบเขตของ repo นี้ — โค้ด ไม่ใช่ข้อสอบ

repo นี้เก็บ **เครื่องมือ** อย่างเดียว **ไม่มีโจทย์หรือเฉลยของ ตลท. อยู่เลย**
คลังโจทย์นำเข้า Supabase จากไฟล์ในเครื่องเจ้าของระบบโดยตรง ไม่ผ่าน git
ทำแบบนี้เพื่อให้ repo ปลอดภัยไม่ว่าจะตั้งเป็น public หรือ private

| อยู่ใน repo | ไม่อยู่ใน repo |
|---|---|
| โค้ดแอป, schema, สคริปต์นำเข้า | ไฟล์ตำรา/ตะลุยโจทย์ (PDF) |
| สคริปต์ที่ *สร้าง* `data/curriculum.json` ได้ | ตัว `data/curriculum.json` เอง (ข้อความ LOS ของ ตลท.) |
| — | โจทย์, ตัวเลือก, เฉลย, คำอธิบายเฉลย |

`node tools/check-no-content.mjs` บังคับกฎนี้ — จะ fail ถ้ามีไฟล์ PDF/XLSX ถูก track
หรือมีไฟล์ข้อมูลที่บรรจุเฉลย **รันก่อน push ทุกครั้ง** (หรือ `npm run check` ทีเดียวครบ)

ระหว่างที่คลังยังว่าง หน้า "ทำข้อสอบ" จะขึ้น **Coming Soon**
และยังใช้ "บันทึกผลจากภายนอก" ได้ตามปกติ

## เครื่องมือฝั่ง dev

| คำสั่ง | ทำอะไร |
|---|---|
| `python tools/curriculum.py <LOS.pdf> data/curriculum.json` | สร้างต้นไม้หลักสูตรใหม่จากคู่มือ ตลท. |

## Deploy (Vercel)

เพื่อนใช้ `localhost` ไม่ได้ ต้อง deploy ก่อนถึงจะเป็นระบบหลายคนจริง

**1. Vercel → Add New Project → import repo นี้**
Framework ตรวจเจอ Next.js อัตโนมัติ ไม่ต้องตั้ง Root Directory (repo นี้คือตัวแอปเลย)

**2. Environment Variables** ใส่ 2 ตัว (อย่าใส่ `SUPABASE_SERVICE_ROLE_KEY` — ใช้เฉพาะสคริปต์ seed บนเครื่อง)

```
NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
```

**3. กลับไป Supabase → Authentication → URL Configuration** เพิ่มโดเมน production

| ช่อง | ค่า |
|---|---|
| Site URL | `https://<โปรเจกต์>.vercel.app` |
| Redirect URLs | `https://<โปรเจกต์>.vercel.app/**` และ `http://localhost:3210/**` |

ใส่ทั้งสองอันได้ ไม่ต้องเลือก — dev กับ production ใช้ร่วมกัน
**Site URL ต้องเป็นโดเมน production** เพราะเป็นค่าที่ลิงก์ในอีเมลอ้างถึง

**4. เพิ่มเพื่อนใน allowlist** แล้วบอกให้เข้าที่โดเมน production

> `/auth/callback` อ่าน `x-forwarded-host` เมื่ออยู่บน production แล้ว
> ถ้าไม่ทำ Vercel จะ redirect ไปโฮสต์ภายในที่ผู้ใช้เข้าไม่ได้

> **Preview deployment ล็อกอินไม่ได้** เพราะโดเมนสุ่มทุกครั้งและไม่ตรงกับ Redirect URLs
> ถ้าจำเป็นให้ใส่ pattern `https://<โปรเจกต์>-*.vercel.app/**` เพิ่ม

## โครงสร้างข้อมูล

```
subjects (11)  →  chapters (69)  →  los (515)
                                      ↑
                  questions ──────────┘   ผูก LOS เพื่อชี้จุดอ่อนได้ถึงระดับหัวข้อ
                      ↑
       sessions  →  attempts        เก็บ chosen / is_correct / seconds / over_budget
```

`sessions.question_ids` เก็บลำดับข้อไว้ตอนสร้างชุด และ **ไม่** สร้างแถว `attempts` ล่วงหน้า
เพราะชุดที่ทำค้างไว้ไม่ควรถูกนับเป็นตอบผิด — ยกเว้นโหมดสนามจริงที่ตอนส่งจะเติมข้อที่ไม่ได้ตอบให้เป็นผิดตามกติกา

## โหมดทำข้อสอบ

| โหมด | เวลา | หมดเวลาแล้ว |
|---|---|---|
| **ชุดเสมือนจริง** (`exam`) | 90 วิ/ข้อ ตามสนามจริง | ตัดส่งทันที ข้อที่ไม่ได้ตอบนับเป็นผิด |
| **ซ้อมตามจุดอ่อน** (`adaptive`) | ผลรวมงบเวลารายวิชา | ทำต่อได้ แต่บันทึกว่าเกินงบ |
| **ตั้งเอง** (`custom`) | ตั้งเอง หรือตามงบ | ทำต่อได้ แต่บันทึกว่าเกินงบ |
| **บันทึกจากภายนอก** (`external`) | กรอกเวลารวม | — |

โหมดภายนอกใช้กับ Practice Exam ทางการของ ตลท. บน finquizz (วิชาละ 25 ข้อ ต้องล็อกอิน SET Member เอง)
ระบบเก็บแค่ผลลัพธ์ ไม่เก็บตัวโจทย์ จึงผูกได้แค่ระดับวิชา ไม่ถึง LOS
